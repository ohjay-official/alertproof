Why a fake can’t pass.

Sealpay decides whether goods leave the stall, so it is built and tested like money software.

Paid

What green means

Before the screen turns green, the trader’s phone has checked every part of the receipt, with no internet:

  • It was signed by the trader’s chosen mint, for exactly those amounts.
  • It is locked to the trader’s key, with no way back for the payer and no second key.
  • This phone has never accepted it before.
  • What lands after the mint’s fee covers the price.

The signature is checked first, so a forged receipt only ever says “Not signed by your mint”, never a story a scammer can explain away.

What it doesn’t promise

  • That the mint stays honest and solvent. It holds the money until the trader cashes out.
  • That a receipt wasn’t also accepted on another phone sharing the same shop.
  • After a restore from the recovery code alone, receipts the old phone took but never collected look unspent to the mint. Collecting often keeps that window small.

How it was tested

Twenty passes so far, each with a different purpose or method, every finding fixed or stated in the open.

132 tests
Every refusal, parser edge cases, fuzzing, and an in-memory mint with real curve maths for every money path.
26 of 26
rules broken on purpose, each caught by a test. This mutation testing runs on every update.
Real mint
A 21-step run on the public test mint: pay, check offline, refuse replays and edits, collect, cash out.
Reviews
Seven review passes by separate AI agents that hadn’t written the code: functional, state and access, financial, adversarial, and final independent reviews. A human review is still to come.
Static analysis
CodeQL and Semgrep on every update, plus npm audit on the libraries.
Proven libraries
The audited @noble libraries for all curve and hash maths. The PIN lock uses the browser’s own WebCrypto.

A small surface

Sealpay is a set of static pages with no server of its own. Scripts load only from this site, the pages may only talk to the chosen mints and the price service, and there are no third-party scripts, no analytics and no cookies. A check after every update fails if any page ever sets one.

Your keys

Checking needs only the public key. The private key comes from a 16-byte seed kept encrypted with the PIN, and is unlocked only to collect, cash out or save a backup. Backups leave the seed out, so a backup file alone spends nothing.
